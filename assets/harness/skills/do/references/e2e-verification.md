# E2E Browser Verification Guide

Evaluator Agent의 Stage 2에서 Playwright MCP를 사용한 E2E 검증 가이드.

## 실행 조건

Stage 2는 **UI route/page/component 변경이 포함된 Sprint에서만** 실행한다.
판단 기준: AFFECTED_FILES 또는 Product Spec에 사용자 화면/상호작용 변경이 있는지 여부.

백엔드만 변경된 경우 Stage 1 (정적 검증)만으로 충분하다.

## 검증 절차

### 1. 앱 서버 구동 확인

Product Spec 또는 프로젝트 실행 문서에 명시된 dev/test server URL을 확인하고,
이미 구동 중인지 확인한다.

server URL을 결정할 수 없거나 서버가 구동 중이 아니면:
- Stage 2를 건너뛰고 Stage 1 결과만으로 판정
- 피드백에 "E2E 검증 건너뜀: 서버 미구동" 기록

### 2. Playwright MCP 접근성 트리 기반 검증

스크린샷 대신 **접근성 트리 스냅샷**을 사용한다:
- 2-5KB vs 500KB-2MB (스크린샷)
- 10-100x 빠른 처리
- 토큰 효율적

### 3. 시나리오 실행

Product Spec의 "E2E 검증" 섹션에 정의된 시나리오를 순차 실행:

각 시나리오:
1. 해당 페이지 네비게이션
2. 접근성 트리 스냅샷으로 요소 확인
3. 사용자 인터랙션 수행 (클릭, 입력 등)
4. 결과 상태 확인
5. PASS/FAIL 판정

### 4. 실패 시 피드백 생성

```markdown
### E2E 실패: {시나리오명}

- 기대 동작: {무엇이 보여야 하는가}
- 실제 동작: {무엇이 보였는가}
- 접근성 트리 스냅샷: {관련 부분}
- 추정 원인: {왜 실패했는가}
```

## 검증 대상 예시

| 시나리오 유형 | 확인 항목 |
|--------------|-----------|
| 페이지 로드 | 주요 요소 렌더링, 데이터 로드 |
| 폼 제출 | 입력 → 제출 → 성공/에러 메시지 |
| 네비게이션 | 링크 클릭 → 올바른 페이지 이동 |
| 데이터 표시 | 테이블/리스트에 데이터 정확히 표시 |
| 에러 처리 | 잘못된 입력 시 에러 메시지 표시 |
